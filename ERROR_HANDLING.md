# Ошибки и уведомления

Проверено 26 октября 2026 года. Проект использует статические HTML-страницы и обычный JavaScript.

## Что было

- Красная плашка сообщала об отсутствии клиента базы при запуске, но не об ошибках запросов каталогов. Повторно обновить или снять плашку было нельзя.
- Всплывающие уведомления использовались для копирования, лимита Кинопоиска, загрузки карточек и некоторых действий. Ограничения количества и повторов не было.
- Статистика уже показывала частично недоступные данные и сохраняла предыдущие результаты. Формы оценок, трейлеры, переводы и тайминги во многих местах уже имели сообщения рядом с соответствующим элементом.
- Часть ошибок добавления, истории плеера, настроек, постеров и заказчиков попадала только в консоль. Некоторые формы закрывались даже при ошибке добавления.
- Общего сообщения об отключении сети, необработанных исключениях и незагрузившихся ресурсах не было.

## Ограничения уведомлений

- Одновременно не больше двух всплывающих сообщений, без очереди устаревших ошибок.
- Одинаковая ошибка не повторяется 30 секунд; сообщения о ресурсах — 60 секунд. Одинаковые сообщения об успешном действии подавляются на 2 секунды.
- Успешное действие показывается 2,6 секунды; ошибка или предупреждение — 8 секунд. Есть кнопка закрытия и поддержка экранных дикторов.
- Красная плашка одна: одновременно показывает до трёх сообщений и количество остальных. Высота ограничена; всплывающие уведомления располагаются ниже плашки.
- Пользовательская отмена запроса не считается сбоем. Ошибки сторонних скриптов без доступных подробностей не создают общего уведомления.
- Общий обработчик выводит подготовленные сообщения через `textContent`; технические ответы сервера не вставляются как HTML.
- Автоматическая повторная отправка изменений не добавлена: при потере ответа сервер уже мог сохранить данные.

## Что нельзя достоверно определить на клиенте

- Проигрывается ли видео внутри стороннего iframe и почему внутри него появилась ошибка, реклама, блокировка или требование авторизации. Событие `load` iframe не доказывает работоспособность видео.
- Точную причину `Failed to fetch`: недоступность сервера, DNS, CORS, расширение и другие ограничения могут выглядеть одинаково. Сообщение перечисляет возможные причины без ложного диагноза.
- Отличие действительно пустой таблицы от строк, скрытых RLS: оба случая могут вернуть успешный ответ с пустым массивом. Для различения нужен отдельный серверный контракт; правила доступа не изменялись.
- Доступность API после события `online`: оно означает восстановление сетевого подключения, поэтому пользователь получает предложение повторить действие, а не сообщение о восстановлении базы.
- Сбой до запуска JavaScript, отключённый JavaScript или незагрузившийся сам `toast.js`. Код уведомлений в этих случаях не выполняется.
- Скрытые ошибки, которые сторонний сервис не возвращает в ответе. Для них нужны журналы сервера или API сервиса. Серверный мониторинг в этой задаче не добавлялся.

## Проверка

1. `npm test`: линтеры, форматирование, сборка статических страниц и автоматические тесты.
2. В DevTools → Network включить Offline: появляется одна плашка. Вернуть сеть: появляется предложение повторить действие.
3. Заблокировать запросы `*/rest/v1/*` и открыть каталог. Без ранее загруженных данных появляется красная плашка; с данными из кеша — предупреждение о старой версии.
4. Убрать блокировку и повторно открыть раздел: успешная загрузка снимает сообщение раздела.
5. Заблокировать `script/roulette.js` и открыть рулетку: появляется уведомление; после снятия блокировки действие можно повторить.
6. Несколько раз вызвать одинаковую ошибку: не должно появляться больше двух уведомлений или потока повторов. Проверить закрытие кнопкой и автоматическое исчезновение.

Браузерная проверка в Chrome выполнена с подменёнными ответами API, без записи в рабочую базу: все четыре страницы, Offline/Online, отказ базы с кешем и без него, ограничение количества и закрытие уведомлений.
